# AI notes for completed learning rooms

Members of an accepted exchange can read a closed room and request AI notes. A request creates a SQL job with a UUID idempotency key. `GET /api/rooms/{roomId}/ai/jobs/latest` returns the newest job or `null`. `POST /api/rooms/{roomId}/ai/jobs` accepts `{ "requestId": "uuid" }` and returns HTTP 202. `POST /api/rooms/{roomId}/ai/jobs/{jobId}/reports` accepts `{ "reason": "UNHELPFUL" }` (also `INCORRECT` or `INAPPROPRIATE`). Every route checks room membership. A room allows three generations; only one may be active.

The API stores a queued job before publishing its ID to `pse-ai-jobs-v1`. A scheduled publisher retries SQL jobs that have no publication receipt. A separate `ai-worker` profile consumes Kafka records, calls Groq, validates the JSON result, and persists `SUCCEEDED` or `FAILED`. Duplicate Kafka deliveries skip terminal jobs. Provider errors have at most three attempts; a missing key and malformed output fail immediately. A provider failure exposes only a safe error code to clients.

Set `GROQ_API_KEY` **only in the worker environment**. Optional settings: `GROQ_MODEL` (default `openai/gpt-oss-20b`), `GROQ_BASE_URL`, `KAFKA_BOOTSTRAP_SERVERS`, `ai.kafka.topic`, and `ai.kafka.group`. Start the normal API, then start a second Spring process with `--spring.profiles.active=ai-worker --spring.main.web-application-type=none` and the same SQL and Kafka configuration. Do not use the worker profile on an API instance. No Groq call occurs in the HTTP request path. The Kafka broker and worker must run for queued jobs to finish.

The prompt includes only the accepted exchange's skill names and up to 20 chat excerpts from the room's creation to closure. The service omits profile fields and board drawing coordinates, and redacts email addresses in excerpts. Learners should avoid putting sensitive information in chat because other personal details in free text may still reach Groq. Handwriting and drawings are not interpreted, so the notes may miss whiteboard-only content. The result is AI-generated, may be inaccurate, and should be reviewed by a learner. Raw provider errors and the key are not returned to the browser.

Tests run without a live Groq key and without a Kafka broker. A live end-to-end provider test needs a configured worker and an accepted closed room. The existing development Kafka Compose file can supply the broker; no new image is required if it is already present.
